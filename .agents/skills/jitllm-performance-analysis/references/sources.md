## Authority for tool semantics

- [Nsight Systems](https://docs.nvidia.com/nsight-systems/UserGuide/) and [Nsight Compute](https://docs.nvidia.com/nsight-compute/ProfilingGuide/): use installed help for version-specific tracing, reports, graph/replay and counter support.
- [Apple Metal tools](https://developer.apple.com/metal/tools/) and [GPU counter profiling](https://developer.apple.com/documentation/xcode/analyzing-apple-gpu-performance-using-counter-statistics): discover CLI availability and distinguish counter replay from concurrent execution.
- [async-profiler CPU engines](https://github.com/async-profiler/async-profiler/blob/master/docs/CpuSamplingEngines.md), [JDK JFR tool](https://docs.oracle.com/en/java/javase/25/docs/specs/man/jfr.html), [NMT limits](https://docs.oracle.com/en/java/javase/25/vm/native-memory-tracking.html), [JMH samples](https://github.com/openjdk/jmh/tree/master/jmh-samples/src/main/java/org/openjdk/jmh/samples): sampling, event coverage, native-memory limits and microbenchmark hazards.

Model economy: deterministic collectors/parsers and bounded verifier tasks are good cheaper-model candidates; cross-layer causal diagnosis, compiler behavior and numerical transformations warrant stronger reasoning. This is a routing policy, not evidence that one model has already been benchmarked against another. Verify actual client/model dispatch; keep performance runs serialized while offline analyses can run independently.
